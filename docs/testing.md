# 验证范围与结果

2026-10-19 在本机 Windows x64 上新建独立 `.venv`，使用 Python 3.12.10、Node.js 24.19.0、Windows PowerShell 5.1 和 Chrome，按 README 执行融合安装与启停脚本。该环境没有复用原程序的 Python site-packages 或云端密钥。

## 安装与启动

- 完整安装 Python 依赖与 `npm ci`，`pip check` 无依赖冲突。
- 检查 CNN、YOLO 模型加载以及 Chrome 无界面启动。
- 实际执行停止、重新安装和启动；健康接口返回 `status=ok`、`vision_configured=true`。
- 服务运行时安装脚本会提前停止并要求先停服务；端口已占用时启动脚本会停止。
- 融合依赖通过 `backend/constraints-fusion.txt` 固定到本次验证版本。OpenCV 5 的变化会导致现有棋面检测回归，因此使用已验证的 OpenCV 4.14.0.94。

## 自动化检查

- 后端：539 项通过、35 项跳过。保留单元、合成棋盘/视频、手工校正、重检、导出等测试。
- 前端：67 项通过，生产构建通过。
- PowerShell 编码回归检查同时检查脚本正文的隐藏 BOM，并实际执行启动脚本前两行，避免只做语法解析而漏掉命令执行错误。

依赖个人录像素材的测试按模块中的 `FIXTURES` 路径是否存在明确跳过；原素材不上传。专用 Node 录像渲染夹具缺失时，只跳过该项渲染测试，其他导出编码与进度测试继续执行。

## 实际流程检查

- 上传一段 5.7 秒、114 帧的真实视频短片，定位棋盘并调用本地模型，得到 25 枚棋子的初始识别结果。
- 自动分析覆盖整个短片，保留 2 条待核对记录；这不是 2 手正确走棋或识别准确率的声明。
- 在单独的人工边界副本中插入步骤、执行区域重检，扫描 82 帧并保留未确定的内容。人工边界用于验证操作链路，不代表视频识别结果。
- 从该副本实际导出 MP4 并重新解码，验证 H.264、1080×1192、60 FPS、180 帧。
- 用 Chrome 打开已保存的真实视频任务：前端代理正常、没有模型未配置提示、没有 JavaScript 页面错误。

以上是同一台电脑上的独立环境验收，尚未在第二台物理电脑上测试。其他操作系统、Windows ARM、不同硬件的速度以及任意视频的完整自动识别效果均不在本次验证结论中。当前仍为需要安装运行环境的源码发布版。
