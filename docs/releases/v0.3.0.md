# v0.3.0：独立双窗口与 CPU 状态

发布日期：2026-10-24。

重复双击 EXE 可打开独立窗口，每个窗口有自己的后台、本机端口、任务库和浏览器配置。窗口1使用应用目录的 `data`、`录屏存放`；后续窗口使用各自的 `instances/<编号>` 子目录。再次启动使用最小空闲编号，可读回该编号保存的任务。停止或关闭一个窗口不影响其他窗口。

右上角约每秒显示 CPU 总量100%、逻辑处理器数、整机已用、本窗口占用与当前空闲。占用按整机100%归一化，包含所属子进程；当前空闲不是独享配额。首次采样或服务失联会明确显示状态。

修复起始局面未建立时只扫描、不生成步骤的问题：遇到不确定占位或棋种，立即进入待核对状态并开放编辑。核对并保存后再次开始解析，已有扫描结果保留。候选棋局不会自动变成已确认局面。恢复较早检查点时保留已有扫描索引指标。

包含本次构建使用的棋盘观测和棋子身份追踪批量处理优化，保留原有识别、推断、人工核对和录像导出流程。

## 验证

- 后台完整测试742通过、1跳过；前端79通过；实例分配5项通过。
- 两个实际 EXE 窗口处理不同视频的约70秒选区，各产生10条步骤记录；51个采样区间同时推进。一个结果仍有待核对步骤，另一个全部确认。
- 初始化有疑点的窗口可立即编辑，经实际界面保存后继续追踪；关闭一个窗口后另一个服务健康。
- 普通启动两个窗口可读回各自历史任务；更新程序文件时两个用户任务库校验值保持一致。
- 尚未验证20分钟完整双开、三/四开持续负载及其他实体电脑；不保证任意视频完全自动还原。

## 使用与更新

下载 `XiangQi-Vedio-Reconstruction-0.3.0-win-x64.zip`，完整解压后双击 `XiangQi Vedio Reconstruction.exe`。请保留整个文件夹；无需安装 Python、Node.js、浏览器或配置云端 API。此构建适用于本机验收过的 Windows x64，未签名。

发布包不包含个人任务、原视频或录屏。更新前退出原程序并备份自己的 `data` 与 `录屏存放`，将这两个目录保留在新程序旁，实例子目录也须一起保留。第三方模型、组件许可及对应应用源码见包内 `licenses`。
