# 不确定走法推断修复与验收

日期：2026-10-21。正式入口：scripts/start.ps1，页面 http://127.0.0.1:5278，后端8278。

## 原因与实际修改

1. 原恢复检查退避到10秒，但连续证据仅保留3秒，反复只剩一帧。改为相邻成组取证，保留限频。
2. 原流程要求未移动棋子的占位、棋种也再次全部确认，低置信度会阻塞后续。新增有限候选搜索：继承历史身份，按合法一步和直接可见占位排序，最多保留5条路径，缺口最多搜索3手。未知位置不当作空格。
3. 增加 predicted_position、匹配分数和依赖步骤。不确定走法立即进入棋盘与棋谱，虚线标落点，文字标“推断待核对”。视频跟随、人工校正和重新校验保留不确定状态；合法性不冒充视觉确认。插入步骤会同步重排推断依赖。
4. 历史身份或漏子若已经使合法走法无法解释连续完整画面，使用现有本地融合识别建立“推断恢复局面”。只接受直接占位支持的棋子，过滤模型在空格上产生的多余棋子；要求完整占位、每方一个将帅。旧差异保留为审核记录，恢复局面和依赖它的走法保持推断，不虚构多子同时走的一步。
5. 恢复识别须持续矛盾2秒，调用间隔至少10秒；跨恢复快照及重启保留冷却。已有严格恢复通道继续工作，不能静默确认不确定起点。
6. 截取选区的尾部延伸只续区间内已观察到离盘的动作：源格连续两次直接判空才取得资格；未知不算；源格在选区前后重新可见占用都会撤销资格。避免把同一棋子的后续回合并入末手。未确认结果冻结保留供核对。
7. 进入局面校正时采用当前推断局面，避免退回过时局面。录制导出副本可承接恢复快照及后续新棋子身份，不改变原记录审核状态。

主要改动：backend/app/move_inference.py、actual.py、tracking_recovery.py、schemas.py、turns.py、analysis.py、recording.py，以及前端replay、Board、MoveList、App、ReviewPanel和类型/样式。复用现有规则和模型；参考Stone Soup的MIT多假设跟踪思路，未添加识别依赖。兼容旧存档，未自动覆盖旧任务。
