# 虚拟棋盘对局录像

用户已确认设计并于 2026-10-12 要求执行。沿用现有工程，不创建新项目。

- 仅录制右侧棋盘 SVG，不录制左侧视频、操作按钮、棋谱列表或声音；保留现有移动、落子、起点和光圈，不添加“吃”“将”文字。
- 用户核对后点击“导出对局录像”。以已保存选区及任务版本生成独立快照，不改变任务、左侧视频或当前回放。
- 去掉原视频等待，沿用 1/2/3 秒每手；初始局面展示一个步间隔，此后每个实际局面变化展示一个步间隔。人工确认不计走棋的审核记录不产生重复片段。
- 初始局面未确认、选区尚未完整分析、分析进行中、存在待复核/未确认步骤或缺失局面时阻止导出，提示具体问题。界面尚未保存的选区/校正不导出。
- MP4/H.264、60 fps、宽 1080 像素；高度取接近现有 476:525 比例的偶数 1192。不补播放棋谱之外的走棋。
- 保存目录固定为 `F:\codex产出\虚拟棋盘对战录制\录屏存放`。文件名包含视频名、选区、导出时间及短唯一标识，不覆盖旧录像；完成编码后才公开最终 MP4。
- 导出异步运行，界面显示进度、失败原因、最终完整路径和查看录像入口。刷新可恢复导出状态。服务中断的导出标为失败，可重新发起。

实现：专用无界面渲染页复用 React Board，用暂停的浏览器动画按帧采样；Node/Playwright 将 PNG 与重复帧数流送给 Python/PyAV 编码。静止阶段只渲染一次并重复编码，避免逐帧截取静态画面。每次只允许一个导出运行；同一版本同一节奏重复请求返回已有任务。

验收：完整性拒绝、版本冲突、审核记录跳过、中文命名与路径、实际 MP4 帧数/尺寸/时长、初末局面和运动中帧、正常 UI 导出/刷新恢复/进度，以及现有回放动画回归。
