# 长视频单次读取与图像计算复用 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 执行本对话已批准的前两项提速方案：共用视频帧流和复用重复计算，保持走棋及疑点判定条件。

**Architecture:** 给现有 stable_events 增加不结束流的逐帧推进方式；将扫描状态封装为可逐帧消费的对象，既供原独立扫描接口使用，也供实际局面分析在同一次解码中喂入。仍保存同版本扫描索引与检测器检查点；云端识别失败时完成剩余本地扫描。固定采样几何预计算；只在分析运行中复用不可写帧、相同参考占位的读取结果，返回独立字典并限制缓存大小。

**Tech Stack:** Python / OpenCV / NumPy / PyAV / pytest。

**Spec:** 本对话用户“提高速度又不降低识别准确率”与“现在进行优化”；优先实施已建议的前两项，不抽帧、不改识别模型或阈值。

## Global Constraints

- 只修改融合实验，保留既存修改；原始视频、原任务棋谱和手动校正不变。
- 所有原始帧仍参与原扫描与跟踪；落点延伸、短动作、遮挡、吃子、拿起放回和疑点回查保留。
- 原扫描索引及中断检测器状态可恢复；离线识别时仍允许本地扫描完成。
- 不访问外部模型 API；使用独立 TaskStore 与真实视频硬链接进行对照。
- 同一来源、相同起始局面、相同选区比较完整走法、时间、局面、疑点及扫描证据，不把更少疑点当成更高准确率。
- 当前已有未提交修改，原地进行有限改动，不提交或推送。

## Review Focus

- 增量扫描每帧不提前结束缓冲动作，最终 flush 与原整流扫描等价。
- 正常识别不再先解码完整选区；恢复、离线及扫描缓存仍正确。
- 缓存不跨修改帧、参考局面或分析线程串用，调用方修改返回字典不污染缓存。
- 几何预计算在严格/非严格、棋盘边缘与遮挡条件下与原算法等价。
- 扫描和走棋进度在运行中同步推进，帧覆盖不减少，清单与后续复刻保持顺序。
