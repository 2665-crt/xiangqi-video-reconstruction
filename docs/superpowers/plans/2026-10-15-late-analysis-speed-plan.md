# 解析后段增长开销整改 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 针对用户反馈“越解析到后面越慢”消除随历史数量增长的重复查询，同时保持原识别与恢复行为。

**Architecture:** 分析中的追加式历史保留全部快照，同时维护完整棋盘签名、占位颜色和历史棋子目录索引；不完整画面不执行原本不可能成功的历史匹配。扫描待处理计数维护有序事件时间，通过二分查找计算。分析中的详情读取直接返回工作进程已校验保存的快照，结束后仍按原方式校验旧数据。通过同帧、同历史数量的前后对照验证增长趋势与输出等价。

**Tech Stack:** Python / NumPy / OpenCV / pytest。

**Spec:** 本对话对速度与准确率的要求，以及最新用户反馈。延续既有优化，不抽帧、不删历史、不修改模型或阈值。

## Global Constraints

- 仅改融合实验；保留所有已有修改及原用户任务数据。
- 索引必须与原反向遍历一样选择最近的匹配，保留悔棋和被吃棋子身份恢复。
- 遮挡不足 90 格时仍返回不能确定，不把未知格当空格。
- 性能对照使用独立存储，不启动外部模型请求，不替换原棋谱。
- 不停止正在运行的用户分析；加载新代码前核实任务状态。

## Review Focus

- 相同棋盘、不同棋子 ID 的历史取最近快照。
- 已被吃掉的棋子仍能通过历史目录识别，当前棋子信息优先。
- 取回历史快照必须复制，不允许调用方修改索引内容。
- 非单调、重复扫描事件时间及恢复水位倒退时计数仍与逐项求和一致。
- 稀疏画面永远不能仅靠历史确认走法；真实视频输出不因索引改变。
