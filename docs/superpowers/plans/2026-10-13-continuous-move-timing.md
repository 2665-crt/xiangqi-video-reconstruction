# 连续走棋与步骤时间整改 Implementation Plan

> **For agentic workers:** 使用 superpowers:executing-plans 在当前会话执行；先失败测试，再实现，最后整体验证与独立审查。

**Goal:** 修复跨视频漏检与丢步、独立记录每步动作时间、点击提前一秒定位、步骤栏右移并与录像区域底边对齐。

**Architecture:** 保留实际局面与规则回放流程，检查逐帧占位跟踪的过滤、短暂落点及疑点覆盖；按棋子动作保存开始和落定时刻，定位时间与同步时间分离。未知顺序不猜造棋谱，以明确疑点保留证据。

**Tech Stack:** Python / OpenCV / FastAPI / React / TypeScript。

**Spec:** 当前聊天中已讨论的要求，用户已明确要求开始整改。

## Global Constraints
- 在 experiments/fusion-recognition 修复正在使用的实验版本；不覆盖原任务和用户校正记录。
- 同一回合同一棋子连续调整合并；不同回合分别保留；规则问题提示并保留审核入口。
- 步骤显示及定位为真实动作开始前 1 秒，最低 0；棋盘同步按真实落定时间。
- 三栏顶部对齐；步骤栏底边与虚拟棋盘的对局录像底边对齐；列表内部滚动。
- 不调用付费云端服务；真实视频验证使用独立输出目录。

## Review Focus
- 快速连续落子、遮挡与不完整占位仍不得静默消失。
- 回到旧局面、吃子、同棋子调整不得错误合并不同回合。
- 一次观察含多个回合不得以同一检测时刻伪装准确时间。
- 人工校正、已有历史任务和恢复操作须兼容新增时间字段。
- 右栏长文本、空任务、窄屏及校正面板不得破坏尺寸和滚动。
