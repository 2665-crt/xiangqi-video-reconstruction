# 棋盘识别与操作识别修复计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修正红黑错认、漏子、拿棋停顿形成虚假步骤及识别过慢。

**Architecture:** 初始局面使用清晰证据和独立占位校验；后续按完整操作更新已知身份，遮挡不提交快照。模型只处理本地无法确定的清晰变化；优化棋盘校正和扫描开销，记录各阶段耗时。

**Tech Stack:** 现有 Python、PyAV、OpenCV、FastAPI、React，不增加模型或依赖。

**Spec:** 本聊天中用户反馈及已讨论方案；用户已明确授权执行。此前只读限制已由本次修复请求解除。

## Global Constraints

- 保留实际摆棋、非合法移动、吃子、悔棋、特殊残局和原视频时间。
- 使用现有 5278/8278 端口，不影响其他服务。
- 不覆盖已有任务或用量，不打印凭证；真实验证使用独立任务。
- 默认本地回归，不批量发起付费模型请求。
- 当前目录没有 Git，不创建工作树或提交。

## Review Focus

- 初始候选唯一但漏子或颜色错误时，不能自动确认。
- 手停住、棋子拿起及无关格遮挡不能生成兵往返或频繁模型调用。
- 清晰真实落子及快速连续变化必须保留；不能靠吞掉所有短动作掩盖错误。
- 模型局部识别不能删除未改变位置的棋子或改写其身份。
- 优化前后棋子数量、身份、变化顺序及绝对时间必须一致。
