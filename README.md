# 棋局复刻 · 真人象棋视频复盘

Windows 本地网页：左侧上传和播放真人象棋录屏，右侧虚拟棋盘逐步复现。第一版不包含录制和视频导出。

## 本项目端口

- 前端：http://127.0.0.1:5278
- 后端：http://127.0.0.1:8278
- 与数据分析 Agent 的 5173/8001 分开。启动遇到占用时报错，不停止其他进程，也不自动换端口。

## 启动

本次开发已经安装项目内依赖。打开工作目录中的 PowerShell，执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

然后在 PC 浏览器打开 http://127.0.0.1:5278。服务后台运行，日志在 data/logs，进程号在 data/runtime.json。已经运行时直接打开页面，不重复启动脚本。

停止或更改模型配置后重启：先运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop.ps1`，再运行上述启动命令。停止脚本核对本项目进程身份和创建时间，保留视频及棋谱，不接管其他项目。

## 配置自动识别

当前选择 `qwen3.8-omni-flash`，地域为华北2（北京）。项目根目录已准备 `.env`，自行填写 `VISION_API_KEY`：

```dotenv
VISION_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
VISION_MODEL=qwen3.8-omni-flash
VISION_API_KEY=自行填写
```

在百炼控制台选择华北2（北京），进入密钥管理，创建或使用该地域的 API Key，填入本机 `.env` 并保存，不需要在对话中发送密钥。配置完成后重启本项目后端。

上述公共接口仍可使用；官方推荐业务空间专属地址。如果控制台调用示例提供专属地址，将 `VISION_API_BASE` 改为 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，其中 `{WorkspaceId}` 替换为实际业务空间 ID，密钥也须属于该空间。参见[百炼接口地址说明](https://help.aliyun.com/zh/model-studio/base-url)。

接口须支持图像输入的 Chat Completions。程序请求 `VISION_API_BASE/chat/completions`，不自动补 `/v1`。密钥不在网页填写，也不会出现在健康检查响应中。模型直接连接指定地址；本程序不继承系统 SOCKS 代理。

`qwen3.8-omni-flash` 请求启用 JSON Object 输出和 `reasoning_effort=medium`，读取最终文本中的棋局 JSON。自动初始化发送一张清晰的棋盘图；本地无法确定的稳定变化发送最多三张前后截图，并提供已知棋子身份和原位置。模型只负责识别画面中的完整局面，不把拿在手里的棋子当成已完成落子；程序随后合并回合并检查象棋走法、轮次和将帅安全。违规观察只作为审核证据，不自动改变复盘棋盘。音频和整段视频输入尚未接入。模型能力与参数见[官方说明](https://help.aliyun.com/zh/model-studio/qwen-omni)和[视觉结构化输出说明](https://help.aliyun.com/zh/model-studio/vision-model)。

使用云端识别会发送裁剪后的棋盘截图，并产生供应方调用费用。OpenCV 在本机逐帧检查校正后的棋盘，只在出现候选变化时请求模型；已经确认的起始截图可用于跳过首个相同稳定画面的重复识别。页面显示检查帧数、模型请求数、图片数和已记录 Token；请求失败也计入请求和图片数，但未必有供应方 Token 记录。请求与图片计数从本次升级后累计，Token 保留历史记录，金额以供应方账单为准。

缺少配置时自动识别按钮不可用，仍可上传、播放、调整棋盘、设置初始棋局和手动逐步复盘。程序不会将内置棋谱冒充视频识别结果。

## 使用 SOP

1. 点击上传或拖入 MP4。初期优先 MP4/H.264、固定视角、棋盘完整、无剪辑跳步，上传上限 2 GiB。
2. 选择任意开始、结束时间。点击“调整棋盘范围”，拖动四角对准棋盘最外侧交叉点；原视频红方在上或镜像时选择对应方向。自动定位结果需要检查。
3. 点击“自动解析并复刻所选区间”。程序保存范围，在可停止的分析子进程中自动初始化。起点有遮挡时逐步扩大前置查找范围，寻找操作前的完整局面；前置画面仅用于追踪身份，不加入选区回放。起始局面唯一时直接复刻，不要求确认下一方。“单独识别起始画面（可选）”及手动初始设置用于主动校正。
4. 无需先剪掉人物；程序只检查校准棋盘区域。同一方、同一枚棋子的连续滑动暂存为一个回合，以对方开始移动前最后一个清晰稳定局面确定最终落点，合并原位置到最终位置的一步；没有对方后续移动时，按所选区间结束时段判断。回到原位置且没有其他变化时不计走棋。合并后的走法必须符合象棋规则。拿走待吃棋子先等待后续落点，避免把吃子误认为对方开始移动。修改时间、四角或方向后自动重新初始化。

   分析期间可随时点击红色“停止分析并保留进度”，终止分析进程并恢复页面操作。已有棋谱、用量和尚未确认回合的候选及证据保留；暂存回合转为人工审核。已被供应方接收的请求仍可能计费。
5. 点击步骤定位原视频。确定步骤可逐步或自动播放；疑点前自动播放暂停。
6. 同方多子调整、非法走法和轮次异常以红色标记并提示人工审核；历史局面回退以黄色标记“疑似悔棋”，原来的走棋步骤保留，倒退操作不自动进入正常复盘。普通合法后退不因方向相反就判悔棋。每一步保存自己的操作前局面，疑点只标记当前步骤；后面清晰的步骤独立检查走法并自动确认，可以直接点击查看和回放。

   点击审核记录，系统先展示判断并预填候选棋子与落点，用户可直接确认或修改。确认按钮保持可点击；缺少棋子选择或走法不合法时明确说明原因并保留填写内容。保存仍须通过规则校验，也可确认“此处不计入走棋”并保留提示。分析过程中也能审核已经识别出的步骤，实时进度不关闭审核面板、不覆盖人工结果。已确认步骤可点“校正此步”。
7. 对照模式跟随原视频；演绎模式按 1/2/3 秒一手复现。右侧显示当前局面总数、红方及黑方数量。结果保存于本机任务，刷新或“打开已保存任务”可恢复。
8. 核对完毕后，在右侧“对局录像”中点击“导出对局录像”。只导出已保存选区的虚拟棋盘及现有动画，不包含原视频、按钮、棋谱列表或音轨。录像采用紧凑节奏：初始局面展示一个步间隔，此后每个实际走棋/局面变化各展示一个步间隔，沿用 1/2/3 秒每手，忽略原视频的等待；人工确认不计走棋的审核记录不会增加片段。

   初始局面未保存、选区分析未覆盖末尾、仍有待确认/待复核步骤，或当前设置/校正未保存时不能导出。界面给出具体原因；导出成功显示 100% 和完整文件路径，刷新可继续查看进度。生成期间不影响原视频和右侧正常回放，不会调用识别模型。修改棋局后，应重新导出新版本。

   文件为 MP4/H.264，1080×1192、60 帧/秒，自动保存到 `F:\codex产出\虚拟棋盘对战录制\录屏存放`。文件名包含视频名、选区、导出时间及短唯一标识，不覆盖旧录像。“查看录像”可播放已完成文件。必须保持前后端服务运行；后台使用已安装的 Node.js、Playwright、Chrome 与 PyAV 生成画面，耗时取决于走棋数量，进度表示已生成帧比例。服务重启导致导出中断时需重新导出。

坐标显示为列 1—9、行 1—10，从虚拟棋盘左上向右、向下，红方在下。

## 识别能力和限制

程序包含：时间戳解码、基础棋盘定位、自适应前置查找、棋子身份及占位跟踪、落子周围手指检查、稳定文字变化检查、多帧视觉请求、回合合并、象棋规则校验及违规审核。识别截图保留棋盘外侧边缘，避免裁掉边线上的棋子文字。新上传和重新分析默认启用本轮规则；既有存档保持原结果，需要重新分析才会生成新的规则棋谱。

后续识别优先沿用已知棋子身份，通过可见起点与落点还原变化；不能唯一匹配的完整局面交给模型。观察到的多子调整、增减棋子不自动作为合法走棋发布。局部遮挡先等待后帧，在同一回合可由后续清晰落点消除时继续合并；无法确定才审核。自动起始画面无法确定下一方时，从首个明确行动方建立轮次；手动设置的下一方严格保留。完整局面重复可能来自合法循环或悔棋，因此只提示疑似回退并交给人工判断，不直接断言违规。

初始画面通过本地颜色及占位验证时，OpenCV逐帧跟踪落点；不适用该检测器的外观沿用稳定画面模型路径。真实视频本地验收覆盖75—200、101.2—140、150—200及198.4—240秒，前三段分别自动还原26、9、5次变化，均保留末尾1处尚未完成或不可确认的画面。起始身份使用此前核对结果，本轮没有新增云端调用；自动起始识别协议通过测试响应验证，尚未重新验收真实云端质量。具体证据见 `docs/迭代进度.md`。

基础棋盘定位优先近水平/垂直棋盘，透视棋盘可用四角人工校准。变化检测保留颜色和局部区域差异，轻微噪声先降噪；棋盘内的手、阴影及镜头晃动仍可能触发候选事件。连续多步且证据不足时进入人工确认，不保证还原任意遮挡。已有真人录屏的初始棋局核对和短片检测记录，整局逐手准确率及一小时真实视频费用仍未验收；一小时静止画面的模拟测试不能替代真实对局。最新结果见 docs/迭代进度.md。

## 重新安装项目依赖

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-lock.txt
Set-Location frontend
npm.cmd ci
```

如果网络使用 SOCKS 代理但新虚拟环境缺少代理支持，先在该虚拟环境安装 PySocks；不要修改其他项目的环境或全局配置。

视觉调用区分连接超时、截图上传超时、等待响应超时、模型服务或网关中途断开、流式响应截断及HTTP错误，安全诊断保存在任务的`vision-last-response.json`。Qwen3.8-Omni-Flash使用流式JSON响应，当前思考强度为none；连接等待15秒、上传等待30秒、无响应等待180秒，持续输出超过300秒时结束请求。

### 网络及模型服务自动恢复

新分析和单独起始画面识别会先保存输入与恢复状态。临时连接故障进入“任务已保存，后台将自动恢复”，普通用户无需反复点击重连。后台按5、15、30、60、120秒逐步延后尝试，之后最多约每300秒一次；供应方Retry-After等待时间同样有效。关闭网页不取消任务，后台服务重启后继续已授权任务；服务关闭或电脑关机期间不执行工作。

恢复从原始输入与已保存成功响应重建完整检测历史，已有棋谱不会清空或重复追加，成功响应不会再次向模型请求。恢复可能需要额外本地解码。接收响应、网关超时等结果不确定的请求最多额外重试两次，超过后由管理员检查，避免无限重复推理及费用；密钥、权限、余额或明确接口配置错误也需管理员处理。

页面保留“立即尝试恢复”和“停止自动恢复”辅助按钮。主动停止会撤销后台恢复；修改选区、初始棋局或校正记录前先停止，修改后旧恢复状态失效。仅当选区分析完整并核对棋局后才允许导出录像。

旧失败任务没有本次新增的恢复日志。点击“检查并恢复任务”会创建独立恢复副本重新处理，原任务和已有棋谱保留；该副本可能重新调用模型，不把它当作旧任务的无损断点续跑。新任务遇到同类故障则自动恢复。
